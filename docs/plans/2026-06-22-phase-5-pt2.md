# Phase 5 Part 2: Deployment & Performance Plan

> **For Antigravity:** REQUIRED WORKFLOW: Use `.agent/workflows/execute-plan.md` to execute this plan in single-flow mode.

**Goal:** Provide a production-ready Docker deployment setup and verify system performance with 100 accounts.

**Architecture:** We will create a multi-stage `Dockerfile` to serve both the Next.js API/frontend and the background workers. We'll add the `web` service to `docker-compose.yml`. Finally, we will write a `scripts/seed.ts` script to generate 100 accounts and 10,000 emails to test Next.js rendering and database index performance.

**Tech Stack:** Docker, Next.js, Prisma, BullMQ.

---

### Task 1: Dockerfile Setup

**Files:**
- Create: `Dockerfile`
- Create: `.dockerignore`

**Step 1: Write .dockerignore**
Ignore `node_modules`, `.next`, `.git`, etc.

**Step 2: Write multi-stage Dockerfile**
Use `node:20-alpine`. Install dependencies, generate Prisma client, build Next.js. Expose port 3000. Command should be overridable for the worker.

### Task 2: Update Docker Compose

**Files:**
- Modify: `docker-compose.yml`

**Step 1: Add web service**
Add `web` service mapping port 3000 to 3000, depending on `postgres` and `redis`.

**Step 2: Update worker build contexts**
Ensure `worker-1` and `worker-2` use the same Dockerfile but override the `command` to `npm run worker`.

### Task 3: Performance Testing Seed Script

**Files:**
- Create: `scripts/seed.ts`
- Modify: `package.json`

**Step 1: Write seed script**
Use Prisma to create 100 `email_accounts`. For each, create 100 `emails`. 

**Step 2: Add npm script**
Add `"db:seed": "tsx scripts/seed.ts"` to `package.json`.

### Task 4: Verification

**Files:**
- Modify: `task.md`

**Step 1: Build Docker Image**
Run `docker-compose build`. Expected: Success.

**Step 2: Run Seed Script**
Run `npm run db:seed`. Expected: 100 accounts created.
